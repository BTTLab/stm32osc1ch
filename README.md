# STM32 DIY Oscilloscope
https://youtu.be/fAIbFj_k99g

A simple USB oscilloscope built around an **STM32F207 Nucleo** board, using its internal ADC, DMA, and a hardware timer to achieve a stable 2 MSPS sampling rate with edge triggering. A Python front-end receives the captured waveform over UART and plots it in real time.

This is part of a video series — this first entry covers a single working channel: ADC + DMA acquisition, hardware-timed sampling, a software trigger with pre-trigger capture, and a minimal Python . Future videos will push the sampling rate further and add multiple channels.

## Features

- Up to **2 MSPS**, 12-bit resolution
- Hardware-timed sampling via TIM2 → ADC external trigger (no CPU involvement in timing)
- Circular DMA buffer, double-buffered via half/full transfer complete callbacks
- Rising-edge trigger with hysteresis and pre-trigger capture
- Non-blocking UART transmission via DMA (921600 baud)
- Simple Python/matplotlib GUI with interactive zoom and pan

## Hardware

- **Board:** NUCLEO-F207ZG
- **Analog input:** PA6 (ADC1, channel 6)
- **Connection to PC:** ST-LINK's virtual COM port (USART3), no external USB-to-serial adapter needed

⚠️ **An input protection circuit is mandatory to keep the input signal within 0 - 3.3V**. Negative voltages or anything above 3.3 V can damage the MCU. An analog front-end (offset + clamping) is covered in the video mentioned above.

## Getting started

### Firmware

1. Open the `firmware/` folder as a project in **STM32CubeIDE**.
2. Build and flash it to a NUCLEO-F207ZG board.
3. Connect a signal to PA6 (respecting the voltage limits above).

### PC-side 

```bash
cd software
pip install -r requirements.txt
python oscilloscope1_ch.py
```

Update the `PORT` variable in `oscilloscope1_ch.py` to match your board's serial port (e.g. `/dev/cu.usbmodemXXXX` on macOS, `COMx` on Windows).

## How it works

1. TIM2 triggers an ADC conversion at a fixed interval.
2. Each converted sample is written into a circular DMA buffer — the CPU is not involved.
3. Once half of the buffer has been filled, the firmware scans it for a rising edge crossing a configurable threshold (with hysteresis to reject noise).
4. When a trigger is found, a fixed window of samples — some before the trigger point, the rest after — is copied out and sent to the PC as a single packet over UART, using DMA so the transfer doesn't block acquisition.
5. The Python script receives the packet, unpacks it, and updates the plot.

## Known limitations

- **~200 kHz** is the practical upper limit for accurately reproducing a signal's shape at 2 MSPS (based on a rule of thumb of ~10 samples per period).
- The trigger can be unstable on **slow-moving signals with noticeable noise** (e.g. a sine wave below ~12 kHz in testing), since the signal spends many samples slowly crossing the threshold, giving noise multiple chances to cross the hysteresis band. Square waves are largely unaffected, since their edges are fast enough that noise doesn't get the chance. Making the sample rate and hysteresis adjustable per frequency range is planned.
- No input protection or offset circuitry yet — analog front-end coming in a future video.
